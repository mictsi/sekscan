# Portable execution — 0.6.2-preview

`portable: true` is the default. The application installs its own executables in
`bin/<tool>/<version>/`, uses native vulnerability caches under `cache/`, and stores
local history in `data/sekscan.db`. No existing PATH-installed scanner satisfies
this requirement, and `tools.<name>.path` is ignored in portable mode.

## Prepare on a connected machine

```sh
sekscan init --home ./workspace
sekscan prepare --home ./workspace --all --with-java --update-tools --yes
sekscan doctor --home ./workspace --all
sekscan db status --home ./workspace --all --with-java
```

CI must explicitly supply `--config ./workspace/sekscan.json`; it must be a trusted
file. `prepare` installs every missing configured tool, even when another copy is
available on the machine. It checks releases and upgrades unpinned managed copies
only with `--update-tools`. Pinned versions and SHA-256 pins are respected. Installing
one copy does not alter the system installation. Syft, Grype, Trivy, Gitleaks, actionlint, Hadolint, zizmor and gosec have built-in
release recipes. Go SDK and govulncheck have managed preparation recipes. `--all` means all entries in the
selected `tools` map, not every tool mentioned in example documentation.

A post-install version probe must succeed. Release downloads use checksums and
available asset digests; publisher signature verification is not yet implemented.

## Retired runtime

Semgrep and its Python preparation pipeline are removed. Legacy settings are
ignored in memory; no files are deleted automatically. See
[SEMGREP-REMOVAL.md](SEMGREP-REMOVAL.md).

## Move the workspace

Stop scans and updates, close the local dashboard/database connections, then copy
the application executable and the **entire workspace** to a machine with the same
OS/architecture and compatible runtime environment. Preserve executable permissions.
Use its new location:

```sh
sekscan doctor --home ./moved-workspace --all
sekscan db status --home ./moved-workspace --all --with-java
sekscan scan dir:/path/to/project --project my-service --home ./moved-workspace --offline \
  --out ./security-report
```

The platform recorded in current.json must match. Binaries are not universal across
operating systems or CPU architectures. Configuration/lock paths generated by this
version are relative. Preserve `config/`, `bin/`, `cache/` and `data/` together. Old
user-authored absolute paths must be replaced manually; initialization never overwrites
them. Installed version metadata is resolved from the managed tree, not its legacy
absolute `path` field. Portable lockfiles belong in the workspace root or `config/`.

The scanner environment has isolated HOME/USERPROFILE, XDG, temporary and language
cache directories under `cache/`. Its PATH contains managed tool directories, not
the host PATH. Built-in actionlint disables optional ShellCheck/Pyflakes subprocesses.
It is **not** a sandbox: arbitrary extensions still run with the user's permissions.
Explicit native configs may reference additional files, services or helpers; packaging
those inputs is the operator's responsibility. Runtime installation is explicit in `prepare --yes` (or approved install-missing).
Go's SDK lives under `bin/go/<version>/`; govulncheck is built therefrom with checksum
verification. Full bundle manifests reject changed/missing/extra files and preserve
relative relocation. Scanner and runtime distributions must be verified on each
platform; no system-runtime or Docker fallback is made. Importing the same version
with different content is rejected rather than silently mutating a lock.

Registry login configuration, custom CA files, cloud credentials, the input source
or container image, and remote SQL servers are external inputs, not automatically
mirrored by prepare. For disconnected container scanning use a local image archive
or rootfs; a registry reference is rejected by offline mode.

## Native vulnerability databases

| Data | Workspace location | Prepared by |
|---|---|---|
| Grype vulnerability database | `cache/grype/db/<schema>/vulnerability.db` | `prepare` / `db update` |
| Trivy vulnerability database | `cache/trivy/db/` | `prepare --all` / `db update --all` |
| Trivy Java identification index | `cache/trivy/java-db/` | `--with-java` |
| Trivy check cache, when downloaded | `cache/trivy/checks/` (upstream layout is version-dependent) | controlled misconfiguration warm-up |
| Go vulnerability DB | `cache/govulncheck/<sha>/` and `current.json` | `prepare` / `db update` |
| Go module/build cache | `cache/go/mod/`, `cache/go/build/` | Explicit `prepare --go-module PATH --yes` / analysis |
| Syft content cache | `cache/syft/` | generated during scans that request enrichment |

Syft, Gitleaks and actionlint do not need a Grype/Trivy CVE database. The Trivy
checks warm-up may use embedded checks when its OCI checks bundle is unavailable;
that does not prove a newer external checks bundle was downloaded. Offline scans
cannot manufacture missing dependency content or Java metadata.

`db status` checks Grype's native validity report, path and age. Trivy readiness checks
metadata, age and a nonempty DB file; Trivy itself validates its actual schema during
scanning. Missing, incompatible or stale required data returns exit 2 instead of success.
The configured `max_db_age` is retained in offline mode. Keep binaries and compatible
DB snapshots together and refresh them on a connected machine when they become stale.

```sh
sekscan db export --home ./workspace --out ./scanner-data.bundle
sekscan db import --home ./moved-workspace --file ./scanner-data.bundle
```

These bundles contain Grype/Trivy supported cache trees and the Go vulnerability
snapshot/manifest, **not tool
binaries, the SQLite history file, or every possible extension/enrichment cache**.
They also exclude Go project module/build caches and custom runtime bundles.
Copy the whole workspace when all local scanner state is required. Go DB freshness
uses the last successful download time; every file is integrity-checked before use.
Only supported downloaded data can be used offline. Preparation never invents missing
dependency code or mirrors private package credentials. See DEFAULT-SCANNERS.md.

## Portable scan-history database

SQLite requires no separate service. To copy history while the source may be open,
create a consistent snapshot rather than copying only the active `.db` file:

```sh
sekscan storage backup --home ./workspace --out ./history-backup.db
```

The destination must not exist. The command uses SQLite `VACUUM INTO`, includes
committed data visible to its snapshot and does not modify the source database.
Copy the snapshot into the stopped destination workspace's `data/sekscan.db`. Do
not overwrite an active destination or mix it with old WAL/SHM files. A quiescent
whole-workspace copy after all connections close is also supported.

PostgreSQL and SQL Server remain shared external services: copying this folder does
not copy their data or start those servers. Use service-native backups and migrations
for them. Choose SQLite or `--no-store` for genuinely disconnected scans.

## Diagnostics and privacy

Application logs stay in `logs/`. Raw scanner stderr is **not recorded by default**.
Use `--diagnostic-stderr` only during local troubleshooting. It writes bounded raw
stderr to separate `*.private.log` files with restrictive file modes where supported.
These files may contain secrets. They are not embedded in reports or shared SQL
artifacts; do not include them in published bundles. Windows directory/file ACLs
must also restrict access appropriately. Log retention remains operator-managed.

## Acceptance boundary

The supplied source has local fixture, relocation and system-SQLite tests. It does
not include downloaded upstream tools, downloaded CVE databases or a newly validated
production executable. Run `scripts/live-smoke.sh --yes /absolute/path/to/sekscan`
on a connected machine to exercise installation, DB downloads, relocation and offline
scanning using actual upstream tools. See TESTING.md for unverified areas.

## Application release platforms

The six application release targets include Windows ARM64. Each external scanner
still needs a compatible native release; the application target alone does not
establish scanner availability. No implicit emulation or system-tool substitution
is used. Semgrep is no longer part of platform preparation or scanning.
